Plain-language reference

How to read an evaluation

Start with whether a model returned usable answers, then examine agreement with the verified reference, and only then compare time and estimated cost.

Research evaluation only

This app measures agreement with configured gold files. It does not establish clinical validity and must not be used for diagnosis or treatment decisions.

Evaluation workflow

  1. Choose models and tasks.Every selected model receives the same task prompt and gold items.
  2. Run the evaluation.The app records model output, errors, tokens, time, and estimated cost.
  3. Compare with the reference.Deterministic code compares parsed answers with the verified gold file. No second model judges the answer.
  4. Interpret in layers.Check response coverage, task results, label-level errors, and efficiency—in that order.

Task concepts

Clinical-language terms

Word
A token counted as an intelligible lexical word under the CIU task rules. Filled pauses such as “um” and “uh” are excluded.
Not word
A fixed transcript token excluded from the word count, such as a non-lexical filled pause.
Correct Information Unit (CIU)
A counted word that is intelligible in context, accurate about the stimulus or topic, and relevant and informative under the configured rules.
Word, not CIU
An intelligible word that counts toward total words but does not satisfy the configured CIU criteria.
Part of speech (POS)
A grammatical category assigned to a token, such as NOUN, VERB, PRON, or CCONJ. This project uses the task's declared UPOS tagset.
Gold file
The clinically reviewed reference answer used for comparison. “Gold” means the configured benchmark—not an infallible universal truth.

M8 metrics

Agreement metrics

Raw token agreement

The share of reference token positions assigned exactly the same label by the model. It can look high when a common label dominates.

Precision

Of the tokens the model assigned a label, how many truly had that label? Low precision means the model over-applied it.

Recall

Of the reference tokens that had a label, how many did the model find? Low recall means the model missed it.

F1

A balance of precision and recall. It is high only when both are high. F1 is reported separately for each label.

Support

The number of reference tokens carrying that label. Treat metrics based on very small support cautiously.

Macro average

The simple average across labels with a defined metric. Each label receives equal weight regardless of frequency. It is not a cross-task score.

Confusion matrix

Rows are gold labels and columns are model predictions. Diagonal cells are correct; off-diagonal cells show which labels were confused.

Mean and SD across repetitions

The mean summarizes repeated runs; standard deviation (SD) shows how much they varied. One repetition cannot estimate variability.

Undefined values: “n/a” means the denominator did not exist—for example, a label absent from both gold and predictions. If a gold label exists but the model never predicts it, precision is reported as 0.

Interpretation order

How to read the report

  1. Coverage first.Review errors, parse failures, truncation, and comparable-response rate.
  2. Use the task headline.Lower count error is favorable for CIU; higher token agreement is favorable for POS.
  3. Inspect labels.Precision, recall, F1, and the confusion matrix reveal errors hidden by an overall number.
  4. Check repetitions and support.Prefer stable patterns supported by enough tokens and items.
  5. Then compare efficiency.Latency and estimated cost matter only after confirming usable performance.

Compare models only within the same task, prompt, gold data, and experimental condition. The app intentionally does not create a single score across unlike tasks.

Ablation studies

Experiments and “closest valid observed”

An ablation run changes one setting—currently maximum output tokens—while keeping the other settings fixed. The baseline is the ordinary configuration.

The report first favors configurations that return comparable answers, then chooses the task headline closest to gold, followed by lower estimated cost and latency. Overview, Efficiency, and Task Detail use that selection by default; the results selector can lock those views to the baseline or one tested token limit.

“Closest valid observed” is exploratory because it is selected on the same gold items shown in the report. For defensible model selection, choose settings on development items and report performance on separate held-out items.

When results look empty

Troubleshooting

Error

The gateway request failed or returned an unsupported response shape. Open the Items tab for the recorded diagnostic.

Parse failure

The model returned text, but it did not contain a valid answer matching the task's JSON schema.

Alignment problem

The answer omitted, duplicated, or added token indices. Special confusion-matrix buckets keep these failures visible.

Truncated response

The model reached its output-token limit. Increase maximum output tokens or use an ablation study to test suitable limits.
